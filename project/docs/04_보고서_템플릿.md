## 3. 최적화 설계와 구현

### 3.1 SGLang 이 이미 하는 것

정직하게 쓴다. 이미 있는 기능을 다시 만들었다면 그렇다고 쓴다. 감점 요인이
아니다. **감추는 것이 감점 요인이다.**

### 3.2 내가 추가한 것

기존 메커니즘과의 차이를 명확히.

### 3.3 구현

- 수정 파일과 핵심 diff (본문에는 요약, 전체는 부록)
- 활성화 플래그: `--enable-xxx`
- 자료구조 / 알고리즘 설명
- **플래그 OFF 시 순정과 동일함을 어떻게 보장했는가**

### 3.4 구현 중 막혔던 지점

무엇을 시도했다 버렸고, 왜 버렸는가. **이 절은 평가에 실제로 반영된다.**
막힘 없이 진행된 프로젝트는 대개 문제를 충분히 깊게 파지 않은 것이다.

## 4. 평가

### 4.1 실험 환경

`setup_pod.sh` 출력을 그대로. SGLang 태그 / 모델 / GPU / 드라이버 / 서버 플래그 전체.

### 4.2 3-bar 결과 ★

| bar | ttft_p50 | ttft_p99 | tpot_p50 | maxitl_p99 | out_tok/s | cache_hit% | slo% | **goodput** |
|-----|----------|----------|----------|------------|-----------|------------|------|-------------|
| default | | | | | | | | |
| ablated | | | | | | | | |
| **mine** | | | | | | | | |

해석에서 반드시 다룰 것:
- ablated ↔ default 간극 = **기존 기능이 이미 주고 있던 이득**
- mine ↔ default 간극 = **내 순수 기여**
- 둘의 비율은? 내 기여가 기존 기능 대비 어느 정도 크기인가?

### 4.3 부하 스윕 곡선

default / ablated / mine 세 곡선. y축은 goodput 과 P99 TTFT 둘 다.

### 4.4 분해 분석

`--by` 로 나눈 결과 (클래스별 / 턴별 / 스키마별). 평균이 감추고 있던 것.

### 4.5 정확성 검증

`bench.verify` 출력 그대로 붙인다. 일치율과 불일치 위치 해석까지.
