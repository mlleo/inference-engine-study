# 평가 루브릭 및 발표 가이드

## 1. 배점

| 항목 | 배점 | 평가 기준 |
|------|------|-----------|
| **1. 워크로드 분석** | 15 | 트래픽 특성을 정량화했는가. "무엇이 어려운가"에 구체적으로 답했는가. |
| **2. 병목 규명** | 25 | **클라이언트 지표 + 서버 로그 + ablation** 세 증거가 모두 있는가. 상관이 아니라 인과를 보였는가. |
| **3. 엔진 수정** | 20 | 동작하는가. 플래그로 켜고 끌 수 있는가. 정확성 게이트를 통과하는가. |
| **4. 평가** | 15 | 3-bar 가 완비되었는가. 부하 스윕 곡선이 있는가. 원시 결과를 제출했는가. |
| **5. 트레이드오프** | **25** | **자기 최적화가 지는 워크로드를 스스로 찾았는가.** 왜 지는지 메커니즘으로 설명했는가. |

**성능 향상 폭 자체는 배점에 없다.**

의도적이다. 이 스터디의 목표는 빠른 엔진을 만드는 것이 아니라 **왜 느린지를
아는 것**이다. 개선폭 0% 로 끝나도, 왜 안 되는지를 증거로 규명한 보고서는
만점을 받을 수 있다. 반대로 3배 빨라졌는데 그게 원래 radix cache 덕분이었다면
큰 감점이다.

## 2. 자동 감점

| 사유 | 감점 |
|------|------|
| 3-bar 없이 숫자 보고 (ablated bar 누락) | −15 |
| 정확성 게이트 미통과 또는 미실행 | −15 |
| 원시 결과 파일 미제출 | −10 |
| goodput 없이 throughput 만 보고 | −10 |
| 자기 워크로드를 유리하게 수정 | −20 |
| 트레이드오프 절에 "손해 없음"이라고 씀 | −20 |
| 환경 정보(SGLang 태그/GPU/플래그) 누락 | −5 |

## 3. 가산점

| 사유 | 가산 |
|------|------|
| 다른 사람 워크로드에서 예상 못 한 상호작용을 발견 | +5 |
| SGLang 업스트림에 이슈 또는 PR 제출 | +5 |
| 실패한 시도를 그 원인 분석과 함께 정직하게 보고 | +5 |
| 5×5 교차 검증 결과를 스터디 전체가 쓸 수 있게 정리 | +5 |

## 4. 발표 (15분 + Q&A 10분)

### 슬라이드 구성 권장

| # | 내용 | 시간 |
|---|------|------|
| 1 | 워크로드 소개 — 실제 서비스 예시로 시작 | 1분 |
| 2 | 무엇이 어려운가 — 숫자 하나로 | 1분 |
| 3 | 베이스라인 측정 결과 | 2분 |
| 4 | **병목 규명 — 증거 3종** | 3분 |
| 5 | 최적화 아이디어와 구현 | 2분 |
| 6 | **3-bar 결과 + 스윕 곡선** | 3분 |
| 7 | **트레이드오프 — 내가 지는 지점** | 2분 |
| 8 | 결론: 언제 켜고 언제 켜지 말아야 하는가 | 1분 |

**4번과 7번에 가장 많은 시간을 쓴다.** 구현 설명은 짧게 해도 된다.

### 라이브 데모 (선택, 가산점 없음)

돌린다면 **미리 녹화해 둔다.** 발표장에서 GPU 파드를 띄우는 데 시간을 쓰지 말 것.

### 예상 질문 (미리 준비할 것)

1. "그거 SGLang 에 이미 있지 않나요?" → 무엇이 있고 무엇이 없는지 정확히
2. "ablated bar 와 mine bar 의 차이가 이건데, default 대비로는요?"
3. "QPS 를 2배로 올리면 어떻게 되나요?" → 스윕 곡선으로 답
4. "다른 워크로드에서는요?" → 교차 검증 표로 답
5. "출력이 바뀌지 않았다는 걸 어떻게 확인했나요?" → verify 출력으로 답
6. "이걸 프로덕션에 기본으로 켜야 할까요?" → 조건부로 답. 무조건 켜야 한다는
   답은 거의 항상 틀렸다.

```
[2] 지목한 병목 (1문장)

[3] 증거
    (a) 클라이언트 지표:
    (b) 서버 로그 발췌:
    (c) Ablation 결과:

[4] goodput 이 꺾이는 QPS 지점:

[5] 하려는 최적화 (2문장 이내)

[6] SGLang 이 이미 하고 있는 것 / 내가 추가할 것의 차이:

[7] 예상되는 트레이드오프:
```

**[3] 의 세 칸이 모두 차 있지 않으면 아직 코드를 시작하지 않는다.**
